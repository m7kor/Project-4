# Lodestone — PS2 Native Recompilation

مشروع لتطوير إعادة ترجمة ألعاب **PlayStation 2** إلى برامج تعمل على الكمبيوتر، مبني على [PS2Recomp](https://github.com/ran-j/PS2Recomp). اللعبة الرئيسية التي نعمل عليها هي **Resident Evil 4 (USA)، النسخة SLUS-211.34**.

نحوّل تعليمات معالج اللعبة EE إلى C++ يُبنى للكمبيوتر، ونطوّر طبقة تشغيل لخدمات PS2 والرسوم والصوت والتحكم والحفظ. بعض الأجزاء، مثل IOP وعمليات الأجهزة، تستخدم التفسير أو المحاكاة داخل هذه الطبقة. الهدف تجربة لعب مستقرة؛ **المشروع قيد التطوير ولم يُثبت تشغيل اللعبة كاملة بعد**.

آخر تحديث: **2026-10-12**. التجارب السابقة وصلت إلى بداية اللعب مع paraLLEl-GS ومترجم VU1، والسرعة ما زالت العائق الرئيسي. [مراجعة الأدوات والتحديثات](docs/REVIEW_20261012.md): 221 اختبارات Python و538 اختبار C++ ومقارنة 800 لقطة VU1 ناجحة. أُعيد بناء برنامج التطوير ونجح اختبار إقلاع محدود على GPU مع سجل الزمن الجديد؛ حزمة المستخدم لم تُستبدل. الأدلة الأقدم تصف النسخة المختبرة وقتها.

أُضيفت [أداة فحص الصوت](docs/AUDIO_CHECK.md) مع تقرير للاستماع عند مواضع الاشتباه. اختبار مستقل أكد إنشاء بيانات النظام وقراءتها بعد إعادة التشغيل؛ حفظ تقدم المرحلة وتعليق الصوت أثناء اللعب يحتاجان اختبارًا مخصصًا.

## تشغيل اللعبة والحفظ

افتح [Play-RE4.cmd](Play-RE4.cmd)، أو [Play.cmd](Resident%20Evil%204/Play.cmd) داخل مجلد `Resident Evil 4`. المجلد يجمع البرنامج التنفيذي وبيانات اللعبة والحفظ، ولا يحتاج إعادة بناء عند تشغيله. [تعليمات الحزمة](Resident%20Evil%204/README.txt).

- الحفظ داخل `Resident Evil 4/saves/`، والبطاقة الخام داخل `saves/cards/`. مسار ملفات البطاقة الآخر داخل `saves/mc0/` و`saves/mc1/`.
- ربط اليد الحديثة تلقائي عبر طبقة التحكم، مع إبقاء رموز أزرار PS2 الأصلية داخل اللعبة. التحقق على كل طراز يحتاج تجربة فعلية.
- تجارب المطور قد تستخدم ملف إدخال مسجل بدل اليد؛ مشغّل الحزمة العادي يزيل إعدادات إعادة الإدخال التشخيصية.

**حزمة المستخدم وبرنامج التحقيق مختلفان:** `Resident Evil 4/Resident Evil 4.exe` هي النسخة المحفوظة للتشغيل. `core/out/build/ps2xRuntime/ps2EntryRunner.exe` هو برنامج البناء والتحقيق؛ تحديثه لا يستبدل حزمة المستخدم تلقائيًا.

## الحالة الحالية

| الجزء | ما تحقق | ما بقي |
|---|---|---|
| إعادة الترجمة | تحليل ELF وخريطة الدوال وتوليد C++ وبناء برنامج Windows | صحة المسارات أثناء اللعب |
| الإقلاع والصورة | حزمة المستخدم تصل إلى العنوان؛ تجارب التطوير الأحدث تصل إلى مكالمة هانيغان وبداية الغابة مع GPU | التوافق بعد بداية اللعب ومقارنة الصورة وتحديث حزمة المستخدم بعد التحقق |
| التحكم | ربط الأيدي الحديثة وتوصيلها وفصلها؛ رموز PS2 الأصلية محفوظة | تأكيد التوقيت والاستجابة أثناء اللعب وعلى الطرازات المختلفة |
| الحفظ | إنشاء بيانات النظام وقراءتها بعد إعادة التشغيل؛ مجلد حفظ خاص باللعبة | حفظ تقدم اللعب واسترجاعه |
| الصوت | SPU2 موصول بمخرج الصوت؛ التجارب الأحدث رصدت انخفاض النقرات بعد إصلاح SIF/IOP | المط الزمني المرتبط ببطء اللعب، والتزامن أثناء اللعب الطويل |
| الفيديو | محاكاة IPU وقنوات DMA 3/4 وسلسلة toSPR؛ فيلم المقدمة يُعرض داخل اللعبة ([IPU_EMULATION.md](docs/IPU_EMULATION.md)) | تزامن الصوت وسرعة العرض ومقارنة الإطارات مع PCSX2 |
| أدوات الجودة | اختبارات الأدوات، تحقق Ghidra/MCP، ومقارنة 800 لقطة VU1 وقياس الزمن الحقيقي | مقارنة فعلية مع PCSX2 على نفس نسخة اللعبة والتحقق من خيط VU مستقل |
| مقدمة PS2 | دراسة مسار الإقلاع | لم تُدمج المقدمة الأصلية |

لا توجد نسبة إنجاز عامة موثوقة: عدد الدوال المترجمة والاختبارات لا يقيس اكتمال اللعب. [CURRENT.md](docs/CURRENT.md) هو مرجع الحالة التفصيلية، و[تتبع الفيديو](docs/RE4_EVENT_READ_TRACE.md) يوضح الأدلة وحدودها.

## ما أنجزناه

### التحليل ومعالج اللعبة

أضفنا أدوات لتثبيت هوية ELF وبصمته، استخراج خريطة الدوال، فحص الفروع وخانات التأخير ومقارنة نقاط الدخول المرصودة بالتوزيع المولّد. أُصلحت حالات عرض المقارنات والفروع ونقل بيانات EE، مع برامج صغيرة معلومة النتيجة تمر بالتحليل والترجمة والبناء والتنفيذ.

التفاصيل: [فروع EE](docs/EE_BRANCH_WIDTH.md)، [المقارنات](docs/EE_COMPARE_WIDTH.md)، [نقل البيانات](docs/EE_MOVE_WIDTH.md) و[نقاط الدخول](docs/OBSERVED_ENTRIES.md).

### الرن تايم والخيوط وقراءة البيانات

طوّرنا خدمات SIF وRPC وتنفيذ وخيوط IOP والمقاطعات وطلبات قراءة القرص. صُححت إعادة تعليق خيط EE وقيمة العودة من التعليق والاستئناف التي تعتمد عليها بوابة الإيقاظ في RE4. الاختبارات المستقلة لهذه التغييرات لا تعني اكتمال اللعبة.

التفاصيل: [SIF](docs/SIF_TRANSPORT.md)، [قراءة القرص](docs/DVD_READ_CONTRACT.md)، [تصحيح تعليق EE](docs/RE4_EE_REPEAT_SUSPEND.md) و[توثيق المشروع](docs/).

### وحدات RE4 والرسوم والتحكم والحفظ

أُضيفت روابط لوحدات اللعبة الأصلية ودورة حياتها، ومنها `sscrn` و`st1_0` و`wep02`. عولج توقيت عرض الإطارات لتثبيت نص الحفظ وشعارات البداية، وطُوّر إدخال اليد وبطاقات الذاكرة وتجميع ملفات التشغيل داخل مجلد اللعبة.

التفاصيل: [وحدات RE4](docs/RE4_SNR2_NATIVE_MODULES.md)، [ثبات النص](docs/INTERLACED_TEXT_STABILITY.md)، [الأيدي الحديثة](docs/MODERN_CONTROLLERS.md)، [بطاقة الذاكرة](docs/MEMORY_CARD_NATIVE_DETECTION.md) و[مجلد الحفظ](docs/GAME_SAVE_FOLDER.md).

### أدوات التشخيص والتحقق

- [مراجع C المطابقة](docs/DECOMPREF.md): أمر `python -m ps2l decompref` للبحث بعنوان دالة في نتائج decompdecomp المحلية وفحص هوية اللعبة وبصمات المصادر والأجسام والأدلة قبل عرضها. [نتيجة تقييم الأداة](docs/DECOMPDECOMP_EVALUATION_20261017.md) توضح فائدتها وحدودها داخل مشروعنا.
- `ps2l run`: تشغيل بمهلة وحفظ السجلات والبصمات والصور المتاحة؛ يتحقق من إعدادات التتبع قبل التشغيل.
- `bootcheck` و`framecheck` و`entrycheck`: فحص التقدم وخصائص الصور ونقاط الدخول المرصودة؛ لكل أداة نطاق إثبات محدد.
- [replay_progress.py](tools/diagnostics/replay_progress.py): التحقق من وصول الإدخال المسجل إلى فترات EE المطلوبة، دون افتراض قبول اللعبة للأزرار.
- [trace_payload_identity.py](tools/diagnostics/trace_payload_identity.py): مقارنة عينات الذاكرة بالملف الأصلي ضمن حدود محددة.
- [pcsx2_reference.py](tools/diagnostics/pcsx2_reference.py): قراءة مرجعية من PCSX2 المتوقف مع التحقق من الهوية وثبات البيانات. اجتازت اختبارات مصطنعة؛ المقارنة الفعلية لم تُنفذ بعد.
- [أدوات الصيانة](tools/maintenance/README.md): جرد الملفات ومقارنة التكرارات وتصنيف كل ملف مع سبب القرار.

التفاصيل: [إعداد التتبع](docs/TRACE_CONFIGURATION.md)، [مقارنة بيانات الملفات](docs/TRACE_PAYLOAD_IDENTITY.md) و[مرجع PCSX2](docs/PCSX2_REFERENCE_TOOL.md).

## البناء والتحقق للمطور

المتطلبات: Windows، Python 3.10 أو أحدث، CMake وNinja وLLVM/clang-cl مع أدوات ومكتبات تطوير Windows اللازمة. Python 3.10 يحتاج `tomli`. [دليل البناء](docs/01-BUILD.md) و[البناء التدريجي](docs/INCREMENTAL_BUILD.md).

نفّذ من جذر المشروع:

```powershell
python -m ps2l status
python -m ps2l verify --profile profiles/SLUS-211.34/profile.toml --elf "game/Resident Evil 4 (USA)/SLUS_211.34"
python -m ps2l build --jobs 4 --target ps2EntryRunner
python -m unittest discover -s tests
```

البناء يختار مصادر وحدات RE4 الثابتة تلقائيًا لمسار التوليد الافتراضي، ويحافظ على اختيار مصدر مخصص موجود في إعدادات البناء. للاختيار الصريح:

```powershell
python -m ps2l build --jobs 4 --target ps2EntryRunner --native-module-source recomp/native/SLUS_211.34/re4-native-modules.cpp
```

للتحقق الموسع من النواة وسلسلة التحويل، أو إجراء تجربة تشخيص محدودة:

```powershell
python -m ps2l verify --build --core-tests --canary
python -m ps2l run "game/Resident Evil 4 (USA)/SLUS_211.34" --timeout 120 --diagnostics
```

نتائج التشغيل تحت `artifacts/runs/`. انتهاء المهلة بكود 124 يعني انتهاء وقت التجربة، ولا يعني نجاح اللعب. اختبارات `canary` لبرامج EE صغيرة معلومة النتيجة، ولا تشهد على لعبة كاملة.

تحقق تنظيم الملفات بتاريخ 2026-10-10: **185 اختبار Python ناجح**، وبناء `ps2EntryRunner` بمصادر الوحدات الثابتة ناجح. توجد نتيجة سابقة لـ **526 اختبار C++** في سجل إصلاح الخيوط؛ لم يُعد تشغيلها لتنظيم الملفات. [سجل Python](artifacts/verification/python-suite-durable-native-source-20261010.log) و[سجل البناء](artifacts/verification/re4-durable-native-source-build.log). أحدث تحقق للمراجعة الحالية: **221 Python و538 C++**؛ [تقرير 2026-10-12](docs/REVIEW_20261012.md).

## المراجع والاستفادة من المشاريع الأخرى

النواة من [PS2Recomp](https://github.com/ran-j/PS2Recomp). استُخدم [PS2 recomp Agent SKILL](https://github.com/hkmodd/ps2-recomp-Agent-SKILL) كمصدر معلومات، ومراجع المستخدم موثقة في [RESOURCE_REVIEW.md](docs/RESOURCE_REVIEW.md).

دُرست مشاريع لفهم الترجمة والخدمات والرسوم والفيديو والمقارنة، ومنها [God of War Recomp](https://github.com/KIexster/god-of-war-recomp) و[OpenGOAL](https://github.com/open-goal/jak-project). نتائج المراجعة والتطبيق والمرشحات غير المثبتة منفصلة في [مراجعة GOW بتاريخ 2026-10-10](docs/GOD_OF_WAR_UPDATE_20261010.md)، [مراجعة OpenGOAL](docs/OPENGOAL_REVIEW.md) و[دراسة حفظ PCSX2](docs/PCSX2_MEMORY_SAVE_STUDY.md). نجاح حل في لعبة أخرى لا يثبت توافقه مع RE4.

تراخيص المصادر والاعتمادات محفوظة مع مكوناتها، ومنها `core/LICENSE`. ملفات اللعبة وBIOS والأكواد المستخرجة منها مدخلات محلية وليست ضمن توزيع الأدوات.

## مواصلة العمل

ابدأ بـ [الحالة الحالية](docs/CURRENT.md)، ثم دليل الجزء الذي تريد تغييره. [STATE.md](docs/STATE.md) يحفظ التاريخ؛ [00-ARCHITECTURE.md](docs/00-ARCHITECTURE.md) يحتوي رؤية تصميمية وتفاصيل تاريخية، فلا يؤخذ وحده كقائمة ميزات منفذة.

الأولوية: قياس الغابة بالزمن الحقيقي، ثم تنفيذ MTVU ومقارنة صحة النتائج وترتيب العرض، والتحقق من التحكم والصوت وحفظ التقدم أثناء اللعب. كل تحديث للحزمة يحتاج دليل تشغيل مستقل قبل استبدال نسخة المستخدم.


تحديث التحقق اللاحق: أُضيف [رصد IPU/DMA](docs/IPU_MMIO_TRACE.md) الاختياري. اجتازت المجموعة 186 اختبار Python و527 اختبار C++ مع الرصد وبدونه، والبناء ناجح. لم تُجر تجربة لعبة بهذا الرصد بعد.
