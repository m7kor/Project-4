# نتيجة تقييم decompdecomp داخل مشروع RE4

اكتملت التجربة المعزولة التي بدأناها لاختبار هل المشروع يختصر علينا تحليل RE4. النتيجة: **مفيد لاسترجاع وفحص دوال محددة، لكنه لم يثبت اختصار عمل طبقة تشغيل PS2 أو تحسين سرعة اللعب**. نحتفظ به أداة تحليل جانبية؛ لا نحول المشروع كله إلى مساره بناءً على هذه العينة.

## ما ثبت فعليًا

شُغّل الفورك `n-delic/decompdecomp` عند النسخة `c1c45c4015c361512ad6d54fcda4907f13620bfe` في بيئة مستقلة. عمل التحليل والمسودات على Windows، واستخدمنا EE-GCC الحر مباشرة لتجاوز تعطل WSL الموجود، دون تغيير توزيعات النظام.

نتيجة العمل المحلية **9 دوال فريدة /340 بايتًا**:8مطابقات آلية وواحدة احتاجت سياقًا وإصلاحًا موثقًا للمسودة. تضم النتائج حلقة، وتفرعًا مع استدعاءات ومتغيرات عامة، واستدعاء غير مباشر. ليست هذه نسبة اكتمال للعبة ولا دليلًا على صحة باقي المصادر.

أُعيد التحقق في ختام التقييم من المجموعات الثلاث التي تغطي المراجع الحالية، باستخدام الحكم الأصلي للفورك وملفات object الموجودة. طابقت الأهداف بايتات ELF الأصلي، ورفضت المقارنة الأهداف المعدلة. أداة `decompref` تعرض المرجع بعد فحص هوية اللعبة وبصمات المصدر والجسم والسياق وتوافق الفهرس مع دليل المطابقة.

## طريقة الاستفادة من الآن

عند التحقيق في دالة، نبحث أولًا عن مرجع مطابق:

```powershell
python -m ps2l decompref 0x001D51A4 --source
```

إذا لم يوجد مرجع، تكون المسودة نقطة بداية للفهم، ثم تُثبت بالمطابقة قبل الاعتماد عليها. لا تُستبدل الدوال السليمة في runtime لمجرد توفر C مطابق، ولا يُعاد البحث في مئات خيارات المترجم دون دليل.

أظهرت التجربة عوائق فعلية: تعليمات لم يستكملهاm2c، وأخطاء صياغة للاستدعاء غير المباشر، واستنتاجات ناقصة للوسائط، وحاجة إلى تعريفات الأنواع الموافقة للمترجم القديم. عولج خطأs64في أداة التجربة؛ ما بقي غير مطابق ظل خارج الفهرس. تعطيل جدولة المترجم لم يضف مطابقات وأفسد بعضها، فبقي الإعداد الافتراضي كما هو.

تقييم الأداة ودمج مراجعها اكتمل. سرعةRE4وطبقة تشغيل الأجهزة والحملة والحفظ أثناء اللعب تظل أعمالًا مستقلة لم تثبتها هذه التجربة.
