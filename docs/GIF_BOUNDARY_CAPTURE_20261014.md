# التقاط أول انحراف في حزم الرسم

v25 ثبت فيها بقاء أول resync عند GPU transfer2261976 على PATH2، loop3/NLOOP8192/reg8/FLG0. تعديل MMI وترتيب الطوابير لم يثبتا حل الرأس. هذه الجولة تقيس الحزم عند دخول GPU بدل تعديل الرسم بالتخمين.

## الالتقاط

إعداد اختياري فقط: `PS2X_GS_CAPTURE_TRANSFER_PREFIX`، `PS2X_GS_CAPTURE_TRANSFER_FROM`، `PS2X_GS_CAPTURE_TRANSFER_COUNT`. العدد1..128، نافذة موجبة بلا overflow. الملفات تُنشأ حصريًا ولا تستبدل نتائج سابقة، ويُوقف الالتقاط عند فشل الكتابة. bytes كاملة حتى32MiB لكل حزمة، وحالة المسار قبل إعادة المزامنة وعند مدخل المحلل وبعده. لا توجد حمولة أو كتابة ملفات خارج النافذة؛ عند تعطيل الإعداد لا توجد ملفات التقاط.

`*.giftrace` يحتوي20 قيمةuint64 صغيرة النهاية (160 بايت)، ثم bytes المدخل دون تعديل:

| الفهرس | المعنى |
| --- | --- |
| 0..7 | magic P2GSTRC1، version1، transfer، path، payload bytes، GS vsync-call counter، FINISH count قبل النقل، resync boolean |
| 8..11 | loop، reg، GIF tag low/high قبل reset |
| 12..15 | الحالة الفعلية عند مدخل GS بعد reset الاختياري |
| 16..19 | الحالة بعد تحليل المدخل |

العداد GS ليس قياس FPS مستقلًا ولا هوية جزء الموديل. الالتقاط لا يشمل VRAM أو writer أو RAM السابقة أو VIF command؛ لا يصلح وحده لإعادة إنتاج الصورة أو لتسمية الخلل في المنتج.

## بوابة صحة الأدلة

اختبار GPU الفعلي يلتقط transfer2/3 فقط، يقارن bytes حرفيًا، ويفحص cursor بعد FINISH وهوية المسار، ثم يعيد استخدام prefix ليثبت حماية الملف السابق واستمرار GS. **603/603** C++، و**274/274** Python. محلل `tools/diagnostics/gif_boundary_inspect.py` يعالج PACKED واستمرار reg، وREGLIST مع padding، وIMAGE بما فيه FLG3 الذي يعامله GS المحلي كـIMAGE. يقارن cursor المتوقع مع exit ويلتزم بالمسار؛ لا يستنتج صحة vertices أو الرسم من هذا التطابق.

أداة الجولة تسجل نافذة الالتقاط في identity، وتمنع اعتبار run ذي نافذة ناقصة دليلًا ناجحًا. أداة مقارنة السرعة تشمل الالتقاط في instrumentation، فلا تعطي قياسًا متكافئًا بين جولة مسجلة وأخرى بلا التقاط.
