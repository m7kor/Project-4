## الفرق المؤثر

OpenGOAL يسترجع كود ألعاب Jak إلى GOAL ثم يبنيه بمترجمه إلى x86-64. يوضح README أن أكثر من 98% من كود الألعاب كُتب بهذه اللغة وأن مفككهم مخصص لمخرجات مترجمها الأصلي. لا يوجد في المصادر المقروءة ما يثبت أن مترجمهم يقبل RE4 أو ألعاب PS2 العامة. لذلك نقل مترجمهم إلى مسارنا ليس اختصارًا مثبتًا.

بيئة التشغيل لديهم منفصلة وتحتوي تنفيذًا لخدمات Sony، وتحميل البيانات عبر OVERLORD، والصوت والعرض. الاستفادة الهندسية: إعادة ترجمة CPU وحدها لا تكفي؛ يجب إثبات عقود هذه الخدمات في مشروعنا أيضًا. هذا استنتاج من توزيع مكوناتهم، وليس ادعاء توافق مكونات Jak مع RE4.

## قرارات التطبيق

| فكرة موثقة عندهم | التطبيق في مشروعنا | الحالة |
|---|---|---|
| مهام استخراج وبناء وتشغيل حسب إصدار اللعبة | أوامر lodestone وبروفايل وهوية ELF؛ توسيع هوية الأصول لكل تجربة | موجود جزئيًا |
| offline tests مع fail-on-cmp | إضافة حالات سلوك مرجعية لعقود EE/IOP؛ عدم تحديث المرجع لمجرد إسكات الفشل | اختبارات canary موجودة؛ مرجع تشغيل اللعبة غير مكتمل |
| أدوات memory_dump_tool وtype_searcher | ربط مواقع الذاكرة المعروفة بمعاني الطلبات وإظهار تغيراتها | التتبع موجود؛ قاموس الحالات يحتاج تطويرًا |
| REPL يتصل باللعبة للفحص والتعديل | البدء بفحص الحالة دون إعادة بناء؛ التعديل الحي يتطلب عقدًا مستقلًا | فكرة لاحقة، غير منفذة |
| أدوات أصول منفصلة | فحص جدول AFS وقراءات القرص دون تغيير الأصول الأصلية | bootcheck أُضيف |

الأولوية الآن فحص قبول قراءات القرص وأسباب رفضها، ثم إثبات نقل DMA واكتمال الطلب، ثم تحميل الأصول والعرض. إعادة كتابة المترجم بلغة GOAL ليست مطلوبة لهذه المشكلة.

## أداة منع التشخيص المتكرر: bootcheck

`python -m ps2l bootcheck <capture> --out <report.json>` يقرأ أدلة التجربة ورأس AFS المحلي. يعرض عدد قطاعات الجدول المطلوبة وعدد القطاعات التي قبلت خدمة CDVD طلبها. يستخدم اتحاد النطاقات فلا تضخم المحاولات المكررة نسبة التقدم. يعرض طلبات القراءة المرفوضة وأخطاء القرص مع أرقام أسطر الأدلة.

`python -m ps2l run <ELF> --timeout 120 --diagnostics --trace-disc` يفعّل تتبع القرص المحدود ويولد `boot-audit.json` تلقائيًا بجانب تقرير التشغيل.

حدود الأداة مهمة: قبول طلب قراءة لا يثبت وصوله عبر DMA أو إكمال parser. غياب التتبع لا يثبت التعليق. رأس الأرشيف من الملفات المحلية الحالية، ولا يثبت هويتها التاريخية وقت التجربة. الصور السوداء وانتهاء المهلة لا يثبتان وحدهما وجود تعليق. الأداة لا تصدر شهادة توافق أو تصلح البرنامج تلقائيًا.

في تجربة `20261006T101556Z-b8a537af` ظهرت طلبات مقبولة لكل قطاعات جدول BIO4DAT الـ11؛ بعد ذلك ظهر رفض قراءة 16 قطاعًا عند LSN=180 ثم رفض متكرر لـ22 قطاعًا من LSN=36، وظهرت أخطاء `0xfd`. سبب الرفض يحتاج قياس معاملات التجزئة وحراس الذاكرة داخل الخدمة؛ لا يوجد بعد دليل يبرر زيادة المخزن أو تجاوز الحراس.
