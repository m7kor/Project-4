# إعداد رصد اللعبة والتحقق منه

يفحص `python -m ps2l.run` إعدادات الرصد قبل إنشاء مجلد نتيجة أو تشغيل اللعبة. قوائم الأهداف والمصادر والتسليح ونوافذ الذاكرة وكلمات EE ومواقعها تقبل 16 عنصرًا لكل قائمة؛ تجاوز ذلك يُرفض بدل قبول قائمة يقتطعها الرن تايم بصمت. تُرفض العناوين غير المكتملة والمحاذاة الخاطئة ونوافذ الذاكرة خارج الحدود.

`PS2X_TRACE_CALL_MEMORY=0xde2140` يقرأ 64 بايت من العنوان نفسه. الصيغة `0x455948:0x40` تقرأ مؤشرًا من العنوان الأول، ثم تضيف الإزاحة؛ النقطتان ليستا جمع إزاحة إلى العنوان مباشرة. يتحقق الرن تايم من المؤشر النهائي أثناء القراءة.

تفعيل `PS2X_TRACE_EE` يعتمد على وجود المتغير حتى إذا كانت قيمته `0`. يسجل `report.json` إعداد الرصد الفعلي في `trace_configuration` دون نسخ بقية متغيرات البيئة.

الاستدعاءات التي تنفذ قفزة J مباشرة إلى دالة أخرى قد تتجاوز مسبار `dispatchGuestBranch`. عند تحليل غياب دخول، افحص الدالة المستدعية واختر أغلفتها أو مصادر الاستدعاء المناسبة. مثال RE4: رصد `2C37A0` وحدها أغفل أغلفة `2C3770` و`2C3788`؛ إضافتهما كشف 209 دخولات تغذية في التجربة `20261010T044310Z-90e4971c`. لا تعني هذه الدخولات وحدها نجاح فك الفيديو.

اجتازت الاختبارات الستة الجديدة مع اختبارات توقف الرصد الأربعة: 10 اختبارات. السجل `artifacts/verification/run-trace-configuration-tests.log`. فُحصت خطة استمرارية الحارس مستقلًا؛ بدأت تجربتها قبل إضافة حقل إعداد الرصد، لذلك لا يحتوي تقريرها القديم ذلك الحقل.
