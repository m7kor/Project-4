# مقارنة بيانات القراءة بالملف الأصلي

الأداة `tools/diagnostics/trace_payload_identity.py` تقارن عينات الذاكرة في تقرير `ee_file_poll_trace.py` بجزء محدد من ملف أصلي. هي إضافة محلية مكملة لطريقة مقارنة الذاكرة المستفادة من GOW؛ لا تنقل عناوينه أو تفترض توافق مفكك الفيديو.

تقبل نوافذ مطلقة متجاورة بالترتيب، وترفض التداخل والفجوات وتغير العرض والحدود غير الصحيحة. تحد الجزء الأصلي بـ64MiB والعينة بـ64KiB. تقارن البايتات مباشرة، وتعرض المواضع المطابقة المتعددة بدل اختيار أول تطابق بصمت. الأصفار تبقى نتيجة غير مثبتة. لا تستبدل تقريرًا سابقًا.

مثال RE4، بعد توليد تقرير التتبع:

```powershell
python tools/diagnostics/trace_payload_identity.py artifacts/research/20261010/movie-payload-identity-trace.json "Resident Evil 4/data/bio4mov.afs" --offset 0x2A280800 --size 31791104 --memory mem_9a3e40 --memory mem_9a3e80 --out artifacts/research/20261010/new-payload-comparison.json
```

النتيجة الفعلية في `movie-payload-identity-comparison.json`: تطابق عينتين من128 بايت عند الموضعين0 و`0xF3800`. المدخل192 في جدولAFS يثبت أن الجزء المختار يبدأ عند`0x2A280800` وبطول31791104. بصمة الجزء `bab0fda58664dd5781c7b988d060d2a7175bc1295194c8b8f70fe55eb98ac6f7`، وتقرير التتبع يحفظ بصمة السجل.

هذه العينات تثبت وصول بايتات الفيديو في موضعين. لا تثبت كامل القراءة أو صحة بقية المخزن أو فك الصور أو اللعب. حد التتبع وصل256 دخولًا؛ عدم ظهور أحداث لاحقة لا يثبت غيابها. اجتازت الأداة7 اختبارات للهوية والمواضع المتعددة والأصفار وعزل الجزء والحدود وتجاور النوافذ وتغير العرض والعينات الناقصة. الدليل `artifacts/verification/trace-payload-identity-tests.log`.
