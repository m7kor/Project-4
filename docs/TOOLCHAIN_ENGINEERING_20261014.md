# مسار فحص الأدوات الموحد

**تحديث اتصال المحاكي:** [الربط الحي وأدوات الصوت](PCSX2_CONNECTION_AND_AUDIO_TOOLS_20261014.md) يثبتان تشغيلRE4 واتصالDebugServer/PINE بعد تحديدBIOS وتصحيح enum غير صالح في probe. الأداة تقرأ مخطط الاتصال الفعلي الآن، وgateيشترط `connection_attempt_valid` إضافة إلى وجود الدليل. نتائج الاتصال القديمة بالطلب `mode=debugserver` لم تكن اختبار شبكة صحيحًا.

يمكن الآن تشغيل فحوص الأدوات بأمر واحد من مجلد المشروع:

```powershell
python -m tools.diagnostics.toolchain_check --snapshots artifacts/research/20261012/vu1_snap_forest --out artifacts/verification/my-tool-check --pcsx2
```

اختر اسم مجلد خرج جديد لكل تشغيل. لا تُمسح النتائج السابقة ولا يعاد استخدامها لقبول فحص جديد. بدون `--pcsx2` تُنفذ فحوص RenderDoc وVU1 وTracy فقط. اللقطات الافتراضية في المثال مأخوذة من الغابة؛ لا تمثل جميع مراحل اللعبة.

## ماذا يفحص الأمر؟

1. وجود الأدوات وبصمات ملفاتها وملفات الفحص قبل التنفيذ وبعده.
2. تحميل RenderDoc ونجاح طلب واجهة الالتقاط، في عملية مستقلة عن اللعبة.
3. تكافؤ حالة ودورات وذاكرة وحزم GIF بين المفسر والمترجم والعامل على اللقطات المحددة.
4. تحويل تتبّع التشغيل إلى Tracy ثم إعادة تصديره، ومطابقة أسماء المناطق وأزمنة البداية والمدد بوحدة nanoseconds.
5. تهيئة جسر PCSX2 وأدواته، مع حقل مستقل لحالة الاتصال بـDebugServer.

التقرير الموحد `summary.json` يحفظ حالة كل خطوة، أمرها، زمنها، سجلات stdout/stderr، سبب الفشل، ومسار الدليل. نجاح خروج العملية وحده لا يكفي؛ يجب وجود تقرير جديد بقيمة قبول boolean صحيحة. المهلة أو النتائج القديمة أو JSON التالف لا تمنح نجاحًا. إذا فشلت مقارنة VU1 لا يُشغل تحويل Tracy على أثر ناقص.

`accepted=true` يعني قبول **فحوص الأدوات وإعادة التشغيل المعزولة** فقط. حقول `game_frame_captured=false` و`full_game_lockstep_tested=false` محفوظة دائمًا في هذا المسار؛ اتصال PCSX2 نفسه يظهر في `pcsx2_debugserver_connected`. لا يقيس الأمر سرعة اللعبة أو جودة الصوت أو حفظ الحملة.

## الأدلة الحالية

[التقرير الموحد النهائي](../artifacts/verification/review-20261014-engineered-toolchain-final/summary.json): فحوص RenderDoc وVU1 وTracy وتهيئة PCSX2 نجحت. الاتصال الحي بـDebugServer بقي false. مقارنة VU1 على24 لقطة و47,949 دورة و36 حزمة رسم متكافئة؛ أزمنة Tracy تمثل subprocess بما يشمل البدء والتجهيز، لا أزمنة إطارات اللعبة.

في المحاولة الأولى نجحت الأدوات لكن اصطدمت أسماء سجل الجسر بسجل العملية الخارجي. حُفظت نتيجة الفشل، ثم فُصلت أسماء `*.process.stderr.log` عن سجل الخادم الداخلي، وأضيف اختبار يستنسخ التصادم ويتحقق من حفظ السجلين. لم يُتجاوز الفشل بتحويل الخرج إلى نجاح.

**التحقق:** عشرة اختبارات جديدة تغطي الدليل الناقص والقديم والمزور، فشل العملية، المهلة، تصادم السجلات، وحدات الزمن والمدد غير الصالحة. نجحت295/295 اختبارات Python. بناء المشغل واختبارات المحرك وbenchmark في بيئة Visual Studio الصحيحة انتهى `no work to do`. لا تغيير محرك C++ أو لقطة RenderDoc من اللعبة أو جولة سماعة جديدة في هذه الدفعة.
