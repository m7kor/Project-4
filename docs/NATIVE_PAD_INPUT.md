# Native DualShock 2 input

The optional native SIO2 bus can now sample the host keyboard/gamepad backend for port 0, slot 0. Its serial protocol implements digital/analog/pressure modes, configuration queries, active-low buttons, axes, pressure bytes and motor mappings. Port 1 and absent samplers return disconnected responses. Queue resets preserve controller negotiation; full device resets restore digital mode. Native PADMAN exchanges and RE4 accepting deterministic input are demonstrated below; physical controller acceptance still needs separate verification.

Protocol reference: the unmodified PCSX2 sources pinned at `646df006a4688063e56c0826e7ea4b8bb0c112c4`, recorded with hashes in `artifacts/research/20261007/sio2-reference/manifest.json`. The protocol implementation carries GPL-3.0-or-later attribution. This does not establish full game compatibility or physical controller rumble output.

## Deterministic integration input

Set `PS2X_NATIVE_PAD_REPLAY` to a CSV path to replace live input during an integration run. This samples game VSync ticks through the same native pad transport; it does not inject OS keyboard events or alter game code, branches, memory-card return values or assets.

The exact header is `begin,end,buttons,lx,ly,rx,ry`. All values are decimal unsigned integers. Intervals are inclusive at begin and exclusive at end, sorted and non-overlapping. Buttons are canonical PS2 active-low bits; Cross is bit 14, Up bit 4. Axis range is 0–255. Outside intervals the controller releases all buttons and centers axes at 128. Invalid fixtures fail explicitly. Size is bounded to 128 KiB and 1,024 events; failed parsing preserves the previous valid fixture.

The earlier fixtures `native-pad-create-system.csv` and `native-pad-create-system-vblank.csv` mistakenly used presentation-frame counts for their intervals. They remain historical evidence of ineffective experiments; they must not be treated as successful native input tests. The corrected fixture `artifacts/research/20261007/native-pad-create-system-ee-vsync.csv` presses Up then Cross three times at **EE VSync ticks 420/440, 500/520 and 580/600**, holding each for eight ticks. It is intended to exercise the known system-data/format prompts on the existing blank native card, not as a general automatic gameplay script. Do not reset existing card storage when repeating tests.

## Selected native RPC diagnostics

`PS2X_TRACE_NATIVE_RPC_SID=0x80000400` enables a separate budget of 64 card RPC traces at the native SIF transport, with at most eight per function (unsupported function numbers share one extra bucket). This reserves room for later operations even when GetInfo polls repeatedly. Each matching request logs its function, lengths, native buffer agreement and mode before validation, then dispatch status and the first reply word if it reaches those stages. Other services cannot consume this budget. The filter must be an exact numeric SID. It changes logging only, not packet validation, guest replies or execution paths. Initialization resets the budgets. This complements the bounded IOP RAM capture rather than interpreting absence from the general 128-packet boot trace as proof that later requests did not occur.

The original captured MCSERV dispatch maps function 0x10 to 0x7CC34, which calls the MCMAN Format import. This agrees with the extended RPC command mapping in [PS2SDK libmc.c](https://github.com/ps2dev/ps2sdk/blob/master/ee/rpc/memorycard/src/libmc.c). In run `20261007T231105Z-5e56872f`, the selected native McFormat PC 0x53114 and GetDir RPC 0x0D produced no samples. Those filters alone do not locate the early failure; the selected-service trace is the next diagnostic.

The revised per-function budget was exercised in run `20261008T024314Z-0e6bdea4`: Init (0xFE) and eight GetInfo (0x01) requests were traced, with only nine of the total 64 slots consumed. All twelve replay transitions occurred, and visually inspected frame 9600 still reports failed formatting. Neither the selected Format RPC nor Format PC was observed. Thus the diagnostic budget is no longer the reason for missing later operations in this trace; inspect the EE decision/API path and requests rejected before the selected-service trace before attributing failure to card erase/write behavior. Evidence: `artifacts/research/20261007/auto-controller-runtime-proof.json`. Actual modern-controller input support is described in [MODERN_CONTROLLERS.md](MODERN_CONTROLLERS.md).
