## التنفيذ والاختلاف الذي كُشف

استهدفت الفرضية الصورة الساخنة `53c46ebcaf7db574` ونقاط MSCNT المقاسة. AOT01 ولّد 255 كتلة. نجح C++ والأثر 964 والمخرجات المرئية، لكن مقارنة 800 snapshot كشفت اختلاف sequence وscoreboards وlatestWrite وnextWriteSequence. أول حقل مختلف في الحالة المصغرة كان `e.sequence` عند الحقل 164، بالقيم 0xa28 و0xa05، في مدخل queue غير فعال. لم يُسقط الحقل من المقارنة؛ الحقول المعلقة جزء من العقد المطلوب.

أظهر التصغير أن عبور رؤوس الكتل المتخصصة القديمة غيّر محاسبة الكتابات والحالة القديمة. AOT02 يحتفظ بجدول المرجع ويتوقف عند كل رأس متخصص، ويولد فقط المقاطع التي كان المرجع ينفذها زوجًا زوجًا، دون fusion جديد لها. نتجت 210 كتل، مع `PS2X_VU1_AOT_COVERAGE=1` اختياريًا فقط. ظل ترتيب readyCycle وsequence والـflags وVF/VI/ACC وQ/P وflush وGIF ظاهرًا للمقارنة الكاملة.

الحالة المصغرة ذات SHA `818b31fa06840c18405bfd9421d3116f81024bdcb77c88356005b33bc70f8c39` محفوظة. اختبار regression يشغّل النسخة القديمة كضابط سلبي فيفشل التطابق، ويشغّل النسخة المصححة فينجح. هذه نتيجة عيب فعلي، وليست mutation مصطنعة تغير قيمة متوقعة في الاختبار.

تشمل مقارنة v2 الحالة المعمارية والذاكرة والحقول المعلقة وتسلسل الكتابات والأعلام، ولا تستثني حقولًا لإخفاء الاختلاف. random operands وqueues حالات اصطناعية، وإن استُعملت معها microcode ملتقطة. هذه الأدلة تثبت الاتفاق مع runtime والآثار المسجلة، وليست جميعها اتفاقًا مع PS2 حقيقي مستقل.

`equivalence-03` استغرق 64.953 ثانية، وoperand-fuzz نحو 2.438 ثانية. المجموعة الكاملة `full-gate-02` استغرقت 279.016 ثانية: **117 مهمة ناجحة و8 اختلافات عتادية معروفة**. تضمنت C++635، وPython المختبر95 وقت تنفيذها، واختبارات الصوت22 وPCM4، وVIF/GIF/DMA وIOP/SIF، وZ3 integer models29 وUBSan952 وفق السجلات. الفحص النهائي بعد إضافة قارئ الذخيرة اجتاز **100 اختبار Python**. لم يُعد بناء C++ بعد هذه الإضافات لأنها أدوات قراءة وتقارير فقط.

الاختلافات العتادية الثمانية: EE branchdelay، COP0 performance، FPU branchdelay/muldiv/sqrt، VU0 macro transfer، memory EE default، VU lower EFU. نتائج 47/55 تخص تنفيذيات مرجع Zmbor المثبتة، وليس hardware gate مبنيًا من AOT02. لم يتغير أي `.expected`، ولم يُقبل المرشح عتاديًا بهذا الوصف.

المحاولة `full-gate-01` فشلت في ثلاثة jobs بسبب قيود Windows لقراءة المسارات وملفات الاختبار؛ سجلاتها محفوظة. أُعيدت ضمن الصلاحيات المصرح بها بعد التحقق من السبب، واجتازت المجموعة. محاولة Python مباشرة بالـTEMP الافتراضي فشلت لأسباب صلاحية ملفات؛ إعادة الاختبار بملفات مؤقتة داخل المختبر نجحت. لم يُغيَّر إعداد أمني أو guard لتجاوز فشل اختبار. سطر `source-coverage blocked` في stdout النهائي ناتج متوقع لاختبار سلبي، وليس نجاح تغطية ناقصة.

## الأداء واللعب

المقارنة المعزولة من سبعة أزواج وخمس عينات لكل جانب رفضت المرشح: 18.506 مقابل 18.585 ns/cycle، ووسيط خفض الكلفة −0.378072%؛ ستة أزواج أبطأ. كل العينات الخام محفوظة في benchmark-01. لا مقارنة AOT للعبة بعد هذا الرفض، ولا ادعاء تحسن FPS. راجع `RE4_PERFORMANCE_ROOT_CAUSES.md` للأرقام الكاملة، وحدود sampler، والتغطية الأصلية 99.873319% ودورات stall البالغة 0.939%.

شُغلت اللعبة مرتين لغرض محدد: profile حديث، ثم تحقق ساعة تسجيل input مع أثر VU محدود جديد. المشغّل الثاني ربط إصلاحًا موجودًا سابقًا في pad وIOP، ولم يعِد كتابة نظام الإدخال. تحقق C++635 أولًا، ثم ظهرت 21 ملاحظة من الموفر الفعلي عند EE59..5460. أُعيد بناء 11 فترة replay بنفس بايتات المحاور، وخرج SHA مطابق لملف الإدخال الأصلي. لا استيفاء اصطناعي ولا اختلاق cycles أو ضغط analog غير مسجل.

فُحصت نسخة مستقلة من Ghidra، دون تحليل شامل جديد أو تغيير القاعدة الأصلية. جدول صادرات ELF ربط getter الذخيرة بسجل العنصر الحالي، حيث العدد مضغوط. ثماني لقطات RAM السابقة من المرجع ومرشح Phase5 تعطي **5→4→3→3**. هذا يحسم عدم ارتداد الحقل الخلفي في تلك العينات، ويترك شذوذ HUD مفتوحًا. القراءات غير ذرية؛ التوقيت قبل/بعد كل لقطة وبصمتها محفوظان. لم تُكتب ذاكرة أو إحداثيات أو أعلام.

لم يتحسن room progression بدليل جديد في هذه الدفعة. الانتقال 0x100→0x101 يبقى دليلًا تاريخيًا صحيحًا؛ لم يُعاد تشغيله تلقائيًا. القتال الكامل، وصحة الأعداء والحملة، وAV sync لم تُثبت. حفظ Phase5 وإعادة التحميل محفوظان؛ لم يُكتب حفظ جديد في التشخيصين الحاليين. مقارنة الصور التاريخية 58/59 مع e179 تبقى ذات فرق غير محلول. تفاصيل الحالات والدليل في `RE4_ARCHITECTURE_GAMEPLAY_MATRIX.md`.

سجّل الصوت فعليًا 137061 عينة ناقصة من 14160000 مطلوبة في آخر عداد. لم تُكبر buffers، ولم يُدّعَ أن PCM يثبت خرج السماعات أو تزامن الصورة. لا يوجد تصحيح صوت أو رسوم جديد مقبول هنا.

## الملفات، إعادة التحقق والنشر

الملفات المعدلة القائمة: `.gitignore` و`tools/run_lab.py` و`tools/lab_regression.py` و`PS2_PROJECT_STATE.md`. الملفات الجديدة تقع في `tools/architecture_*.py` و`tests/test_architecture_*.py` وملفي observer/counters من نوع `.inl` والتقارير. القائمة الدقيقة والبصمات في `artifacts/architecture/final-01/source-files.json` وmanifest، والـcommits المحلية في `RE4_ARCHITECTURE_COMMITS.md` بعد تثبيتها. العمل القديم غير المتعلق لم يُستبدل أو يُدرج تلقائيًا.

يمكن إعادة التحقق من التنفيذيات المحفوظة دون تغيير النتائج السابقة:

```text
python tools/architecture_validate.py equivalence-repeat-01 architecture-aot-02 architecture-aot-state-02
python tools/lab_regression.py full --candidate-dir lab/architecture-aot-02 --baseline-dir lab/phase4-suite-02 --project4-recompiler lab/phase4-fixed-01/ps2_recomp.exe --vu-aot-coverage 1
```

تحتاج بوابات Windows الصلاحيات العادية التي تسمح بقراءة مراجع المسارات؛ كل نواتج الأوامر تبقى داخل المختبر. أدوات الإنشاء ذات أسماء التجارب الثابتة ترفض الكتابة فوق نتيجة موجودة عمدًا. لا تُشغّل اللعبة ضمن هذه الأوامر افتراضيًا. الأصول والبطاقات والآثار وGhidra والتوليد وdisassembly خاصة وغير مشمولة في patch.

آخر كتابة GitHub تاريخية فشلت بـ`403 Resource not accessible by integration`. القراءة الحالية أظهرت صلاحية push في metadata، وهذا لا يثبت قدرة integration على الكتابة. لم تتم محاولة كتابة جديدة، ولا تعديل اعتماد أو طلب صلاحيات موسعة. بقي التغيير محليًا مع patch مصدر فقط ووصف Draft PR مرفق؛ لم ينشأ PR ولم يحدث push أو merge أو ترقية تنفيذية.

## النواقص ذات الأثر الأكبر

1. عقد حدود كتل VU أقل كلفة مع الحفاظ على جميع pending state، يسبقه فصل ديناميكي لكلفة body/retirement/XGKICK/flush؛ لا مزيد من توسيع تغطية ثبت أنها مرتفعة أصلًا.
2. trace input بشري جديد بساعة الضيف لمسار الانتقال الفعلي، ثم حالات قبول القتال والتحميل والحفظ بعد الغرفة التالية.
3. تحديد كاتب HUD ومقارنة pixels بالحقل الخلفي عند حالة ضيف متكافئة؛ لا تصحيح game logic دون إثبات.
4. خط زمني متزامن EE/IOP/SPU2/host مع قياس AV وخروج السماعات لتحديد سبب underruns.
5. قياسات GPU وCPU متزامنة وحواجز EE/VU/IOP قبل قرار MTVU أو native service إضافي أو renderer بديل.

النتيجة الحالية لا تستحق ترقية حزمة اللاعب. لا يوجد قياس يثبت 0.5x أو 1.0x، ولا ضمان أن إصلاح VU وحده يكفي للوصول إلى السرعة الحقيقية. بقي المشغّل المعتمد والحفظ والأصول الأصلية كما هي.
