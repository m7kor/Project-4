# رصد IPU وقنوات DMA

أُضيف رصد اختياري في `core/ps2xRuntime/src/lib/ps2_memory.cpp` لتحديد ما إذا كانت اللعبة تصل فعلًا إلى سجلات IPU وقنوات النقل، بدل الاستنتاج من دخول دالة التحكم وحده.

## التفعيل والنطاق

وجود متغير البيئة `PS2X_TRACE_IPU` يفعّل الرصد، حتى لو كانت قيمته `0`. أزله لتعطيله. أداة التشغيل تحفظ وجوده في `trace_configuration.ipu_mmio_enabled`.

السجل يشمل نطاق سجلات IPU `0x10002000..0x10002030`، FIFO `0x10007000..0x1000701F`، وقناتي DMA `0x1000B000..0x1000B080` و`0x1000B400..0x1000B480`. الرصد عند واجهة سجلات الذاكرة فقط؛ لا يشمل أي مسار يجاوزها مباشرة.

- `op=write`: طلب كتابة قبل تطبيق سلوك السجل؛ ليس دليل اكتمال DMA.
- `op=read`: قيمة سجل IPU التي أعادها [نموذج IPU](IPU_EMULATION.md) للمعالج (منذ 2026-10-10).
- `op=read-stored`: لسجلات DMA وFIFO، القيمة المخزنة قبل تطبيق دلالات القراءة؛ ليست بالضرورة القيمة المعادة للمعالج.
- `[IPU census]`: إحصاء أوامر النموذج عند الأعداد 1 و2 و4 و8...، مع نفس المتغير. التفاصيل لكل أمر تحت `PS2X_TRACE_IPU_MODEL` فقط، لأنها سطر لكل كتلة أثناء الفيلم.
- القراءات المتكررة لنفس العنوان والقيمة لا تُكرر. حدود منفصلة: 1024 كتابة و256 قراءة متغيرة، مع إشعار واحد عند محاولة تجاوز كل حد.
- لا يغير الرصد سجلات الضيف. منذ 2026-10-10 السجلات ينفذها نموذج IPU فعلي؛ الرصد يسجل ما رآه المعالج ولا يثبت وحده اكتمال فك SFD.

## التحقق

اختبار الذاكرة يتحقق من حفظ القيم وملاحظة تغير CMD ورصد عنوان DMA، ومنع 100 قراءة متطابقة من توليد 100 سطر. يُشغّل مع الرصد وبدونه. اختبار Python يتحقق من تسجيل وجود المتغير دون تسريب بقية البيئة. سجلات البناء والاختبارات تحت `artifacts/verification/`.

لم تُنفذ تجربة RE4 بهذا الرصد حتى وقت كتابة الوثيقة؛ سبب توقف الفيديو ما زال يحتاج دليلًا فعليًا.

النتيجة النهائية: 186 اختبار Python و527 اختبار C++ ناجح. المجموعة الأصلية شُغلت من `core/` مع الرصد وبدونه، وكلاهما أعاد 0.
