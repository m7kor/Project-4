## الدافع ونطاق التغيير

كان beginNextReady يفحص خريطة الخيوط عند كل تحديث حتى عندما لا يوجد خيط جاهز، ثم nextWakeCycle يعيد فحص التأخيرات. صار يحتفظ بالنتيجة السلبية وبأقرب موعد إيقاظ. قبل الموعد، ودون تغيير في الجدولة، يعيد الخمول مباشرة. عند الموعد يفحص الخيوط ويطبق ترتيب الأولوية ثم رقم الخيط نفسه.

النتيجة المحفوظة تُلغى عند واجهات تغييرات الخيوط والانتظار والإشارات والبطاقات البريدية، وإشارات الأحداث الداخلية، وبدء/انتهاء/إلغاء RPC، والتأخير والنوم ونهاية الشريحة والحذف وإعادة التهيئة. كل تغييرات حالة الخيوط الإنتاجية الموجودة في البحث تقع داخل IopKernel؛ مستخدم المؤشر الخارجي ينفذ CPU ثم يعود عبر endTimeslice. لا يُحفظ خيط جاهز أو مؤشر خيط، ولا تتغير دورات الضيف أو مواعيد DMA أو المؤقتات أو vblank أو SPU2. يبقى التحكم بالمقاطعات مفعلاً في سياق الخمول.

## التحقق

أضيف اختبار لإيقاظ تأخيرين مختلفَي الأولوية عند موعديهما بالضبط، واستمرار موعد جهاز أقرب، وبدء خيط جديد أثناء الخمول، وحذف التأخير وإعادة التهيئة. اختبار ثان يغطي إشارة semaphore من المقاطعة، وإشارة حدث داخلي، وبدء/إكمال/إلغاء/إعادة بدء RPC أثناء الخمول. اختبار صندوق البريد الموجود صار يمارس الخمول قبل حذف الصندوق أيضاً.

بناء الاختبارات نجح في 16.9 ثانية، والتحقق العام اجتاز 497 اختبار C++ و106 Python وثلاثة فحوص أدوات، جميع المجموعات بنتيجة صفر. الأدلة في `artifacts/verification/iop-idle-cache-build.log` و`iop-idle-cache-tests.json`.
